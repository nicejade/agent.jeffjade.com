title: Agent OS 模式

把 Agent 理解成一个小型操作系统，会比“高级聊天框”更准确。它需要任务调度、上下文管理、工具接口、权限控制、状态记忆和日志反馈。

## 六个核心模块

### 任务层

任务层决定 Agent 要完成什么。好的任务描述要包含目标、约束、成功标准和交付格式。

### 上下文层

上下文层回答“Agent 应该知道什么”。包括项目文件、历史对话、用户偏好、外部文档和当前状态。

### 工具层

工具层回答“Agent 能做什么”。常见工具包括浏览器、终端、文件系统、数据库、日历、Issue 系统、设计工具和消息平台。

### 权限层

权限层决定哪些操作可以自动执行，哪些必须人工确认。Agent 系统越接近真实世界，这一层越重要。

### 记忆层

记忆层保存长期经验。记忆不是越多越好，关键是可检索、可更新、可删除。

### 反馈层

反馈层让 Agent 发现自己是否走偏。测试、日志、截图、审阅、用户确认和评分都属于反馈。

## 一个可复用模板

```text
目标：
  我希望 Agent 完成什么？

上下文：
  它必须知道哪些资料、偏好、限制？

工具：
  它可以读取或调用哪些系统？

边界：
  哪些操作需要确认？哪些信息不能访问？

检查：
  什么结果算完成？如何验证？

沉淀：
  这次经验是否要变成模板、技能或文档？
```

## 为什么普通人也需要这个模型

即使你不写代码，也可以用同样方式使用 Agent。比如规划旅行：

- 任务：三天行程。
- 上下文：预算、出发地、偏好、同行人。
- 工具：搜索、地图、订票网站。
- 边界：不自动付款。
- 检查：价格、时间、交通是否可行。
- 沉淀：下次旅行模板。

这就是 Agent 思维的价值：把模糊愿望变成可执行系统。
