[hermes-agent](https://github.com/NousResearch/hermes-agent) 是 Nous Research 推出的开源 Agent 项目，核心方向是长期运行、持续学习、沉淀技能，并支持多模型与多平台入口。

## 为什么它值得关注

很多 Agent 工具偏向“一次会话解决一次任务”。hermes-agent 的吸引力在于把 Agent 当作长期工作者：它可以保留记忆、积累技能、连接消息渠道，并运行在你自己的机器或服务器上。

这意味着它更像一个个人 Agent 操作系统的底座，而不只是一个命令行助手。

## 适合的场景

- 个人知识库整理与长期项目跟踪。
- 定期报告、周报、资料监控。
- 多模型实验与工具调用评估。
- 自托管 Agent 网关。
- 团队内部自动化助手原型。

## 入门路径

### 1. 先在低风险环境运行

不要一开始就连接生产系统。先使用单独目录、测试 API key、非敏感资料，让 Agent 完成几个可检查任务。

### 2. 建立记忆边界

长期记忆越有用，越需要治理。建议把记忆分成三类：

- 偏好：写作风格、常用工具、输出格式。
- 项目：当前目标、目录结构、长期约束。
- 经验：解决过的问题、可复用技能、失败原因。

### 3. 让技能可审计

技能系统的价值在复用，但技能也可能过期。每个技能都应该包含适用条件、输入输出、依赖工具和失效信号。

## 与 Claude Code 的分工

Claude Code 更适合深入具体代码库，做短到中期的软件工程交付。

hermes-agent 更适合长期在线、跨渠道、跨项目、沉淀记忆和技能。

两者可以互补：hermes-agent 负责长期任务与记忆，Claude Code 负责进入某个仓库完成工程执行。

## 评估维度

选择长期 Agent 时，建议看这些问题：

- 它的记忆存在哪里？
- 工具调用是否可审计？
- 是否能切换模型供应商？
- 是否支持本地或自托管部署？
- 出错后能否回滚、重试或人工接管？
- 技能是否能迁移到其他 Agent 系统？
