## Agent 时代的提示工程

- 与传统 Chat 提示的根本区别
- Claude Code 不是"一问一答"，而是"指挥执行"
- 提示的目标：让 Agent 准确理解意图，自主规划执行

## BMAD 方法论

| 阶段 | 含义 | 关键动作 |
|------|------|----------|
| **B**rief | 明确目标 | 说清楚要达成什么，而非怎么做 |
| **M**aterial | 提供素材 | 参考文件、约束条件、验收标准 |
| **A**ction | 指定行动 | 是探索、规划还是直接执行 |
| **D**etail | 细化细节 | 边界条件、禁止事项、风格偏好 |

## 上下文管理策略

- 引用文件：`@filename` 精确指定上下文
- 分阶段对话：复杂任务拆成多个短会话
- 适时 `/compact`：释放上下文空间
- 避免信息过载：给 Claude 需要的，而非全部

## 迭代优化节奏

```
研究（理解现状）
  → 规划（设计方案）
    → 执行（实施变更）
      → 审查（验证结果）
        → 重复或完成
```

- 每一步的具体操作
- 何时需要迭代，何时一条指令足够
- 识别 Agent 陷入迷茫的信号

## 常用提示模板

- "阅读 <文件>，理解后为 <模块> 写单元测试"
- "搜索所有使用 <模式> 的地方，重构为 <新模式>"
- "检查 <PR 链接> 的安全问题，输出报告"
- "为 <项目> 生成 CLAUDE.md"

## 常见反模式

- 提示过于模糊："帮我改进代码"
- 一次性要求过多：超过上下文窗口的复杂任务
- 缺少约束：没有定义代码风格或禁止事项
- 过早微观管理：对 Agent 的每一步指手画脚
