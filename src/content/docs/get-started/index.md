---
title: 为什么 Agent
description: 从普通自动化到 Agent 工作流，理解 Agent 适合做什么、不适合做什么，以及如何开始。
---

Agent 不是“更会聊天的机器人”，而是能围绕目标持续调用工具、读取上下文、执行步骤并根据结果修正路线的工作方式。它的核心价值在于把“想法”和“可交付结果”之间的空白缩短。

## 一句话定义

Agent = 模型能力 + 工具权限 + 上下文记忆 + 反馈闭环。

如果一个系统只能回答问题，它更像助手；如果它能读取资料、编辑文件、运行命令、检查结果、继续修正，并把重要经验沉淀下来，它就进入了 Agent 的范畴。

## 什么时候值得用 Agent

适合 Agent 的任务通常具备四个特征：

- 目标可以被描述，但路径需要探索。
- 过程中需要查资料、改文件、调用工具或比较多个方案。
- 结果可以被检查，例如测试、截图、表格、草稿、清单或日志。
- 任务会重复出现，值得沉淀成模板、技能或工作流。

不适合直接交给 Agent 的任务也很明确：高风险决策、不可逆操作、缺少检查标准的主观判断，以及需要隐私或合规边界特别严格的场景。

## 三层入门路线

### 1. 对话型 Agent

从普通人最容易理解的任务开始：整理资料、写计划、解释概念、比较选择、生成清单。重点不是“让它一次答对”，而是把目标、约束、偏好和检查标准说清楚。

### 2. 工具型 Agent

让 Agent 接入真实工具，例如浏览器、文件系统、日历、表格、终端、设计稿或知识库。这个阶段要开始设计权限边界：能读什么、能写什么、哪些动作需要确认。

### 3. 长期型 Agent

长期 Agent 会积累记忆、技能和偏好。它适合个人工作台、团队运营、研究跟踪、自动化报告、代码维护等场景。hermes-agent 这类项目就是这一方向的代表。

## 关键原则

Agent 时代最重要的能力不是写提示词，而是设计可验证的工作系统：目标清楚、上下文完整、权限可控、结果可检查、经验可复用。
